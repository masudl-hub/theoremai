# v0.3.1

## Summary

`@theoremjs/studio` opens your project's agents, runs them, and saves your edits back to your files. Providers are now data. You register a provider once, and each model binding names a protocol and a provider. Detection is one setting, `guardrails.detect`. A new `embedding` profile type returns vectors.

## What's New

- **`@theoremjs/studio`, first release.** Run `npx theorem-studio` to open the profiles that your setup file (`studio.setup.ts`) registers. Edit a profile as a form or as code, and run it beside the editor. The studio saves the edit to your files. The command needs Deno. To show the studio in your own Vite app, use `studioVite` from `@theoremjs/studio/vite` and `StudioScreen` from `@theoremjs/studio/ui/studio-screen.tsx`. Serve its drafts with `createStudioDraftHandler` from `@theoremjs/studio/server`.
- **Protocols and providers as data.** A protocol is the code for one API shape. A provider is an address, the protocols it serves, and a sign-in. Register a provider once with `registerProvider` (or `scope.providers.register`), then bind models with its `.model()` helper. All of these come from `@theoremjs/agents`:
  - protocols: `openAi`, `openRouter`, `openRouterImages`, `geminiInteractions`, `geminiLive`, `systemOne` (decisions), `geminiEmbedding`, `openRouterEmbedding`, and `ollamaEmbedding`;
  - providers: `openRouterProvider`, `geminiProvider`, `localProvider`, and `typesafeProvider`;
  - your own: `defineProtocol`, `extendProtocol`, and `defineProvider`.
- **Embedding profiles.** A profile of type `embedding` turns text or supported media into vectors. Call `runEmbedding` from `@theoremjs/agents`. In React, serve it with `createTheoremEmbeddingHandler` from `@theoremjs/react/server`, and read it with `useTheoremEmbedding` or show it with `TheoremEmbedding` from `@theoremjs/react/ui`.
- **Detectors.** `guardrails.detect` sets what each detector does (`ignore`, `flag`, `redact`, or `block`) at each boundary it reads. The detectors are `ids`, `financial`, `network`, `credentials`, `injection`, `tool_instructions`, `canary_leak`, `prompt_leak`, `marker_leak`, `ungiven_images`, `ungiven_links`, and `tool_leak`. To add your own detector, give it a dotted key, such as `acme.codenames`. Then set `patterns` or a `find` function. `guardrails.blockedReply` sets whether a blocked reply is rewritten (`retry`) or refused (`refuse`).
- **Key vault with resolvers.** In `@theoremjs/agents`, a `KeyVault` slot can now hold a string, a JSON object, or a function (`CredentialResolver`). The kernel calls the function when a call signs with that slot. Each model can pick its own slot with `models.*.keySlot` and `models.*.fallbackKeySlot`.
- **Host-kept conversations.** The handler keeps the transcript and the model's history in a `TheoremConversationStore`. Use `createMemoryConversationStore` for one instance. Use `createSealedConversationStore` to keep nothing on the host: the browser carries a sealed ref that it cannot read or change. `TheoremChat` and `useTheoremChat` resume a chat from the ref that `onConversationChange` reports. `startConversation` opens a chat on content that the host wrote.
- **Agent tools.** A tool of `type: 'agent'` runs one turn of another registered profile. `AgentToolDef` from `@theoremjs/agents` describes it.
- **Page tools.** A function tool with `answeredBy: 'page'` is answered by the browser. Pass the answers as `pageTools` to `useTheoremChat`, `TheoremChat`, or a live call. On the server, `createMemoryPageToolBroker` from `@theoremjs/react/server` carries the answer back.
- **Tool steps.** With `tools.parallel: true`, the calls of one step run at the same time. `invokeToolStep`, `runTool`, and `runToolStep` from `@theoremjs/agents` run tool calls without a model.
- **Context for a turn.** Declare `inputs.context` to accept facts for a turn. The page (`client`) or the host (`server`) sends them. The chat sends `context` with each turn. The handler adds the host's with its `context` option.
- **Live calls.** `live.greeting` makes the agent speak first. `live.resumed` sets what the agent says when a call comes back after a drop. `LiveCaptionsPanel` from `@theoremjs/react/ui` shows the captions.
- **Streaming drafts.** A turn streams `structured_draft` events for a structured reply and `tool_draft` events for tool arguments. A tool's output streams as a `draft` phase.
- **Profile settings.**
  - `outputs.validation.items` checks each item of a list in a structured reply.
  - `turnBehaviour.atStepLimit: 'answer'` makes the last call at `maxSteps` without tools, so the model answers.
  - `speech.style` and `speech.speed` set the delivery. A turn's `speech.style` or `speech.speed` replaces the profile's.
- **Retries.** Every protocol call retries a transient failure: status 408, 429, 500, 502, 503, or 504, or a network error. It waits 1, 2, 4, then 8 seconds, or what a `Retry-After` header asks. It retries at most 4 times. The waits of one call stay within 5 seconds in all. When the next wait would pass that, the last answer goes back as it came.

## What's Fixed

- A tool server's `402 Payment Required` was a plain tool failure. It is now an `auth` failure, as a provider's is. A `429` from a tool server is now `rate_limit`.
- The session cookie that `createTheoremHandler` sets ended when the browser closed. It now lasts 30 days, so a returning visitor keeps their session.
- Tool schemas sent to Gemini were cut to a subset of JSON Schema. They now go as written.
- Gemini Interactions changed a tool call's argument names to snake case in history. The names now go back as the model wrote them.
- Gemini failed the whole call when a tool result held a document or audio. That part now moves to the next user input, with a marker where it was. OpenRouter does the same for a file that a tool message cannot hold.
- `guardrails.taint.afterRemoteRead` was accepted on a live profile but not enforced. Live sessions now enforce it for each cycle.
- The `financial` detector redacted long numbers that passed the Luhn check, such as IDs in map links. A number now counts as a card only when a card network issues it, and never inside a web address.
- A tool input that failed its schema sent two failure events, and the settled one had no field errors. It now sends one failure, and `failure.details` holds the field errors.
- A Gemini speech request with no voice failed upstream. It now fails before the call with a `config` error that names `speech.voice`.

## Breaking Changes

- **`createProvider` is removed.** Register providers before profiles. Then pass `ProviderHostOptions` (`vault`, `fetch`, `wait`, `limits`, and `openWebSocket`) where you passed a provider. This applies to `runTurn`, `compactHistory`, `runSession`, `runDecision`, and the `provider` option of `createTheoremHandler`.

  ```ts
  // 0.3.0
  const provider = createProvider(profile, { vault: { main: key } });
  for await (const event of runTurn(request, provider)) {}

  // 0.3.1
  registerProvider(geminiProvider, { keySlot: 'main' });
  registerProfile(profile);
  for await (const event of runTurn(request, { vault: { main: key } })) {}
  ```

  Also removed: `CreateProviderOptions`, `OpenAiGatewayConfig`, `LocalProviderConfig`, `GeminiOptions`, `ModelProvider`, `ProviderCompleteRequest`, and `ProviderEvent`. `runSession` no longer takes `gemini`, and `runDecision` no longer takes `endpoint`: set the address in the provider's `connection`.
- **Protocol and provider IDs changed in model bindings.** The fixed lists `PROTOCOLS`, `PROVIDERS`, `PROTOCOL_PROVIDERS`, and `PROFILE_TYPE_PROTOCOLS` are removed. Use `listProtocols` and `listProviders`. Update each binding:

  | 0.3.0 | 0.3.1 |
  | --- | --- |
  | `provider: 'google'` | `provider: 'gemini'` |
  | `protocol: 'openAi'`, `provider: 'openrouter'` | `protocol: 'openRouter'` (images: `openRouterImages`) |
  | `protocol: 'decision'` | `protocol: 'systemOne'` |

  Also removed: `isValidPair`, `isValidProfileProtocol`, `protocolsFor`, `protocolsForProfileType`, `providersFor`, `coerceProtocol`, `coerceProvider`, and `ProfileTypeProtocol`. The `Protocol` and `Provider` types moved from `@theoremjs/agents/schema` to `@theoremjs/agents/providers`.
- **Key slots moved.** The profile's top-level `key` and `fallbackKey` are removed. On a model, `key` is now `keySlot` and `fallbackKey` is now `fallbackKeySlot`. To set a slot for every model of a provider, pass `keySlot` and `fallbackKeySlot` when you register the provider.
- **Protocol settings moved into `models.*.options`.** `cache` (OpenRouter), and `store` and `persistViaInteractionId` (Gemini Interactions), now sit under `options`. `models.*.server` is removed: register `localProvider` with `connection: { baseUrl }`.

  ```ts
  // 0.3.0
  { protocol: 'geminiInteractions', provider: 'google', apiId, store: false, persistViaInteractionId: false }
  // 0.3.1
  { protocol: 'geminiInteractions', provider: 'gemini', apiId, options: { store: false } }
  ```
- **Two subpaths are removed.** `@theoremjs/agents/providers/local` (`createLocalProvider`) and `@theoremjs/agents/providers/google/live` (`openGoogleLiveSession`, `GoogleLiveConnection`, and `OpenLiveWebSocket`) are gone. Use `localProvider` and `geminiProvider` with the `geminiLive` protocol from `@theoremjs/agents/providers`.
- **Guardrail settings are detectors.** Move each removed profile field to `guardrails.detect`:

  | 0.3.0 | 0.3.1 |
  | --- | --- |
  | `guardrails.canary` | `guardrails.detect.canary_leak` |
  | `guardrails.promptEcho` | `guardrails.detect.prompt_leak` |
  | `guardrails.sanitizeInput` | `guardrails.detect.injection` |
  | `guardrails.redactSensitive.{credentials,financial,ids,network}` | `guardrails.detect.{credentials,financial,ids,network}` |
  | `guardrails.egress.checks.images`, `.links` | `guardrails.detect.ungiven_images`, `.ungiven_links` with `allow: { hosts, fromTools }` |
  | `guardrails.egress.onBlock`, `.maxRetries` | `guardrails.blockedReply.onBlock`, `.maxRetries` |
  | `guardrails.egress.enforce`, `.holdback` | A detector of your own under a dotted key in `guardrails.detect` |

  These exports are removed: `egressPolicy`, `EgressPolicyOptions`, `EgressEnforcer`, `EgressRule`, `EgressChecks`, `EgressOnBlock`, `EGRESS_ON_BLOCK`, `ProfileEgressSpec`, `ResolvedEgressSpec`, `CompiledEgressRules`, `UrlCheck`, `DEFAULT_HOLDBACK`, `LIVE_DEFAULT_HOLDBACK`, `standardEgressEnforce`, `collectEgressHits`, `runEnforcer`, `sanitizeText`, `redactSensitiveOnly`, `detectText`, `detectionForProfile`, `detectionForTrust`, `DetectionOptions`, and `SANITIZE_RULES`. To scan text, use `detectAt` with `resolveDetect`. `compileEgressRules` and `compiledEgressModule` are now `compileDetect` and `compiledDetectModule`, and the CLI command `egress-compile` is now `detect-compile`. `directiveHits` and `looksDirective` are now `directives`, and `DIRECTIVE_RULES` is now `DIRECTIVE_SIGNALS`.
- **Lexicon is now labels.** The profile field `lexicon` is now `labels`. Rename the exports:

  | 0.3.0 | 0.3.1 |
  | --- | --- |
  | `overrideLexicon`, `resetLexicon` | `overrideLabels`, `resetLabels` |
  | `lexiconText`, `lexiconDefault` | `labelText`, `labelDefault` |
  | `LEXICON_KEYS`, `LexiconKey`, `LexiconOverrides`, `LexiconParams` | `LABEL_KEYS`, `LabelKey`, `LabelOverrides`, `LabelParams` |
  | `CLIENT_LEXICON_KEYS`, `ClientLexiconKey` | `CLIENT_LABEL_KEYS`, `ClientLabelKey` |
  | `withPublicWording` | `withPublicLabels` |
- **Turn limits.** A profile with no `maxSteps` now stops at 20 model calls. Before, it had no limit. Also, `allowContinue: []` alone no longer stops automatic continuing. Set `autoContinue: []` too.
- **Tool tiers.** A tool is core (`T0`) or on demand (`T2`). `T1` is no longer a valid `loadTier`. Use `T2`. To load some `T2` tools at the start of a turn, return their ids from `tools.t1Policy`.
- **Smaller renames and removals.**
  - `PLAYGROUND_AUTH_TYPES` and `PlaygroundAuthType` are now `STUDIO_AUTH_TYPES` and `StudioAuthType`.
  - `createProfileRegistry` now takes `(tools, schemas, providers?)`, and `createToolRegistry` takes `(findProfile?)`.
  - `sanitizeHistory` no longer takes `(history, options, hits?)`. Its new reader argument is internal. To scan history text, call `detectAt` at the `history` boundary.
  - `LiveSession.sendContext` now takes a `TurnContext` object keyed by sender, not a string. The profile must declare `inputs.context`.
  - `MediaPayload`, `MediaTokenFamily`, `mediaTokenFamily`, `SpeechGuardrailsSpec`, and `JEV_USD_PER_MILLION_INPUT_TOKENS` are removed.
  - `clientAnsweredHandler` is removed from `@theoremjs/agents/surface`.
- **React: chats are kept on the host.** `createTheoremHandler` now needs a `conversationStore`, unless the profile sets `providerContinuation.history: 'stateless'`. The chat resumes from a conversation ref, not a snapshot:

  ```tsx
  // 0.3.0
  <TheoremChat endpoint="/api/chat" initialChat={snapshot} onChatChange={save} />
  // 0.3.1
  <TheoremChat endpoint="/api/chat" conversation={ref} onConversationChange={saveRef} />
  ```

  In `useTheoremChat`, `initial` and `onChange` are now `conversation`, `conversationView`, and `onConversationChange`. `ChatSnapshot`, `applyTurnResultToTranscript`, and `turnInputFromSession` are removed. `walkAway`, `checkWalkAway`, and `SettledToolGate` are removed from `@theoremjs/react/server`. `LiveSessionClient.sendContext(text)` is now `setContext(context)`.

## Notes

- **Peers.** `@theoremjs/agents` now needs `zod` `^4.6.5`. `@theoremjs/react` now needs `@astryxdesign/core` and `@astryxdesign/theme-neutral` `0.7.0`.
- **Versions must match.** `@theoremjs/studio` pins `@theoremjs/agents` and `@theoremjs/react` to its own exact version. Install all three at `0.3.1`.
- **Upgrade order.** Register providers before you register profiles. A profile that names an unknown provider fails at registration.
- **New defaults.** The `credentials` detector now redacts credentials from a reply by default. A speech profile now reads its whole input aloud: the script is no longer wrapped in `<user_data>`.
