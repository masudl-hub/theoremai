# v0.3.3

## Summary

The model now reads back what it wrote earlier in its turn, so it goes on from its answer after tools or an inject. A stage handler can tell the kernel how much of the reply the user already has, and the rest leaves the turn when the inject lands. A tool that the page answers can now run in a headless turn with an in-process coordinator.

## What's New

- **In-process tool execution.** `createMemoryToolExecution` from `@theoremjs/agents` returns a `ToolExecutionCoordinator` that keeps claims and outcomes in process memory. A page-answered tool needs a claim, so pass it as `execution` on `TurnRequest` together with `pageExecution`. You no longer write a claim ledger for a turn that one process serves from start to end. Its `MemoryToolExecutionOptions` take `maxOperations` and `maxOutcomeBytes`, both unset unless you set them. When the coordinator is full, it refuses new operations and keeps the ones it has. If a turn can resume on another worker or after a restart, write your own `ToolExecutionCoordinator`.

  ```ts
  import { createMemoryToolExecution, runTurn } from '@theoremjs/agents';

  const events = runTurn({
    profile: 'assistant',
    input: { text: 'Pick a date' },
    execution: createMemoryToolExecution(),
    pageExecution,
  });
  ```

- **Drop the draft the user never got.** A `StageResult` with `inject` at `post_tool` or `before_end` on a text turn can set `released`: the number of characters of the attempt's reply text that the user already has. Count the text of the `text` events you received, blank lines included (see What's Fixed). When the inject lands, the reply text past that count leaves the model's history and the reply. Tool calls and tool results stay. The model then writes the rest of its answer after the part the user has. Leave `released` out when the user has all of the reply.
  - The `stage` event that reports the landing carries `released`. `keptReply` from `@theoremjs/agents` cuts the reply at that count, so your final text is what the user has plus what the model writes next.
  - A `released` that is not a whole number of 0 or more, or a `released` without an `inject`, gives the stage warning `inject_released_invalid`. Nothing drops.
  - Live turns speak as they go, so they ignore `released`.

  ```ts
  onStage: ({ stage }) =>
    stage === 'before_end'
      ? { inject: [{ role: 'user', content: 'And the fern?' }], released: shownLength }
      : undefined,
  ```

- **Download a trace from the trace panel.** The trace panel has a Download trace button after the turn arrows at its top right. It saves the conversation's trace records as `<agent>-<time>.trace.json`, the file the studio's Replay exchange opens.
- **Replay exchange opens JSONL traces.** Besides a `.trace.json`, it takes a `.jsonl` file with one `TraceRecord` on each line, as `jsonlSink` writes them, and opens it the same way. A line that is not JSON names its line number.
- **Replay exchange follows the whole exchange.** A record that another agent wrote for a call the replayed agent made, under its `traceparent`, now plays in the turn that made the call. A compaction record holds no turn and is skipped. A file that also holds a different agent's own turns is refused, and says so. When the replay reaches a tool result that the file does not hold, it stops, names the tool, and offers Continue live. A trace written in another version of the format says which version it is and that the studio reads version 3.
- **See what a model call was given.** In the trace panel, a model call shows System instructions, the system prompt it was sent, and Tool definitions, each tool it was offered with its description and parameters. Both are folded until opened. A turn shows the same for its first model call.
- **Waiting messages show their kind as an icon.** In the composer's drawer, a steering, queued, or stashed message starts with an icon, and hovering it says what the message will do. The send menu shows the same icon beside Queue, Steer this reply, Send now, and Stash.
- **Set the gap raised panes keep from the page's edges.** Set `--theorem-pane-edge` on a containing element, for example `0px` where the page around the panes is already inset. The default is 12px at the end and 12px or 16px at the bottom.
- **Tool data shows its images.** When a tool result holds a list of parts (`{ type: 'image', mimeType, data }` and the other kinds of `InteractionPart`), the data view draws them in order. Text shows as text, images and videos show as thumbnails that open in one lightbox, and audio shows as a voice note. The base64 `data` of a part no longer counts toward the size past which tool data shows only as JSON.
- **Cards fill their space like a wall.** A tool's data view puts its figures, charts and images in one set of columns. Each card goes under the shortest column so far, so a short card never leaves a hole beside a tall one. A card keeps its place in the page's tab order, and a change of width moves it without drawing it again.
- **The studio's controls sit with what they change.** Each row in the studio's tree has a Reset button on hover, before its remove button, while it differs from how it started: an agent, one of its sections, one of its models, a tool, or a provider. Undo in the toast brings the edits back. Test guardrails is at the top of the Guardrails page. Manage keys is above the providers list. Get code is beside the editor's view toggle. In the preview's header, Import trace is now Replay exchange, and Replay exchange, View trace, and Open in a new tab show their names. `resetAgentNode` from `@theoremjs/studio` resets one row of an agent's tree.
- **Focus the chat's composer from your code.** `chatRef` now also gives `focus()`, which puts the keyboard in the composer. In the studio, Clear history uses it: the button leaves with the conversation, and the keyboard now goes to the new chat's composer, not to the page.
- **An agent opened in a new tab takes its keys from the studio.** The tab that Open in a new tab opens has no Keys button. When the agent runs on your own keys, the tab asks the studio tab that opened it for them, and the keys stay in the memory of the two tabs. If that studio tab is closed, the new tab asks you to set your keys in the studio. A project's agent runs on the project's server, so its tab needs no keys.

- **Set a model's limits in its profile.** A model in a profile can set `limits`: the points at which Theorem stops its calls, such as `operationTimeoutMs` or `maxStepEvents`. The `limits` in the host options of `runTurn`, `runSession`, `runDecision` and `runEmbedding` override them, one field at a time. In the studio, the model's Limits section sets them.

  ```ts
  models: {
    main: {
      protocol: 'openRouterOpenAi',
      provider: 'openrouter',
      apiId: 'openai/gpt-5',
      limits: { operationTimeoutMs: 300_000 },
    },
  },
  ```

## What's Fixed

- **The builder reads why a compactor or a host detector failed.** Before, a failed compaction gave only its error kind, and a host detector's `find` that threw gave only the signal `find_threw`. Now a compaction's `failure.errorInternal` and the trace's `failure_reason` say why it failed. A failed `find` puts the detector and its reason in the guardrail event's `errorInternal`, and in the message of the request it stops. `forClient` strips both for a visitor. The text still stops, as before. The trace cleans that reason with the same failed `find`, so it stores the event's `errorSummary` as `error_summary` instead: the detector, how it failed, the error's type and an error id that the host stream's reason ends with. It holds no text from the host.
- **A failure keeps the kind of what happened.** Before, an HTTP or MCP tool read every failure it threw as `network`, including a cancel, a timeout, and a host `resolveHost` that threw. A decision read any `TypeError` as `network`, and read `internal`, `config`, `safety`, `blocked` and `input` failures as `malformed_response`. A page tool that ran with no execution coordinator read as `unavailable`, and its `errorInternal` held the label "the model isn't available". A connection that dropped while a reply streamed read as `internal`. Now each one keeps its kind. A remote tool's cancel reads as `cancelled`, its timeout as `timeout`, and anything else it threw as that error's kind, with code `request_failed`. A decision keeps the kind of the error under it. A page tool with no coordinator reads as `config`, a full memory coordinator as `config`, and a coordinator that breaks its contract as `internal`. In each case `errorInternal` says what was wrong. A dropped connection reads as `network`, and the text that came before the drop stays.
- **A tool call that never reached its destination says so.** Before, the kernel took a tool's execution claim before its last checks ran. A call that failed at a limit place or at its first address check was saved with effects `unknown`, though nothing was sent. A call that stopped there was saved as uncertain. It read as `unavailable` with "This action has an unresolved execution", and the same operation could not run again. Now the claim is taken at the hand-off: right before the handler runs, the page dispatch, or the first send of an HTTP or MCP call. A failure before it saves as not started, and a stop leaves no record. An error after the claim keeps the kind of its cause, such as `cancelled` or `network`, and still reads with the unresolved-execution copy. A call to run an operation that is still running or uncertain reads as the new kind `conflict`. Each of these errors, and each refusal of the React handler's page dispatch, now says in `errorInternal` what it found. Before, `errorInternal` held only the user's copy.
- **The builder reads why an error happened.** Before, `errorInternal` and the trace's `exception.message` held only the error's own message. When the error wrapped another one as its `cause`, that reason was lost. Now `describeError` adds a `caused by:` line for each error in the chain. A provider error keeps its cause, and keys are removed from each line. A profile build that fails on a host's code also keeps its cause, and it reads as `internal`, not `config`.
- **The model reads the text it wrote before its tool calls.** Before, a step's text did not go into the turn history, only its tool calls did. The next model call did not see what the model had said before it called the tools. Now the history holds the step's text (or its structured reply), then its tool calls, then their results.
- **A `before_end` inject continues the answer.** Before, the answer the model had just written was not in the turn history when a `before_end` inject landed, so the model answered again from the start. Now the answer goes into the history first, then the inject, and the model goes on from its answer. A provider checkpoint also stays valid across this inject. Before, the turn gave a `provider_warning` with code `provider_state_rebuilt` and reason `history_changed`, and the next call went without the saved state.
- **Text from two model calls no longer runs together.** Before, when a reply went on after tools or an inject, the first word of the new call joined the last word of the earlier text ("…full picture.Here's"). Now the host gets a blank line (`\n\n`) before the new call's first text. This happens only when the earlier text ends without whitespace and the new text starts without whitespace. Structured replies get no blank line. The turn history keeps the text as the model wrote it.
- **A steer stays in the conversation.** Before, a steer left the composer's pending list when the turn took it in, but it never showed in the transcript. A host that keeps the conversation also left it out of the saved history, so the next turn's model did not know it was sent. Now the transcript shows the steer where the reply took it in, between the reply before it and the reply after, and the history holds it there too.
- **A finished reply shows whole at once.** Before, when a reply's stream ended, the chat went on revealing the rest of the text it already had. Now the reply shows in full as soon as its stream ends.
- **The composer no longer bounces when you scroll.** Before, the chat had two scrollers, one inside the other, and scrolling past either end of the conversation moved the composer. Now the conversation is the only scroller, and it does not bounce at either end.
- **Stop and Send now keep what the reply said.** Before, stopping a reply, or sending a message now while it streamed, dropped the stream. A host that keeps the conversation saved the stopped reply under a ref the page never got, so the page drew the conversation without it, and the next turn's model did not see it. Now `stop()` asks the host to stop the turn (`POST /stop`, `transport.stop`), the stream ends cancelled, and the page gets the saved reply. What the reply said stays in the transcript and the history, closed as cancelled. A queued message stays queued after a stop.
- **The studio does less work on each change.** Before, the studio checked every tool's schemas again for each agent that used it, every time it compiled the workspace, and its tree worked out a reset for every row of every agent on each render. Now the kernel converts and checks a tool's schemas once, the studio reads each schema text once, and an agent at its start skips its rows' resets. A console page also reads its width once, not on every streamed event. Opening a node or choosing which agent to chat with no longer compiles the workspace or the project's files again, and no longer asks a project's server to load the same edits again. The tool library is masked once for the session copy, not on every write. A click now draws the page once: the editor no longer draws again when no issue changed, the compile wait no longer draws the whole page again, and the tree's hover buttons draw again only when they change.

- **An embedding agent in a project no longer opens as a chat.** Before, the studio's preview showed a project's embedding agent as a chat; now it shows it as an embedding, as it does for an agent made in the studio. Open in a new tab is turned off while a project's server cannot serve the agent, and its tooltip says why.
- **Download trace saves in every browser.** Before, the trace panel freed the file's address in the same moment it started the download, and some browsers then saved nothing. Now it frees it after the download starts.
- **The studio's compaction carries the turn's metadata.** Before, a compaction that the studio ran had no `metadata`, so a compactor or trace that read it got nothing. Now it gets the turn's `metadata`, as `runTurn` gives it.

- **The studio's editor says what it does.** Discard all now says that Undo brings the edits back, and every Undo message in the studio stays 15 seconds; before, Discard all said it could not be reversed, and three of the four Undo messages left after 5 seconds. A speech agent's Format offers the formats the kernel takes, and on a Gemini model it says Gemini cannot make mp3; before, it said only OpenAI models make mp3, though OpenRouter makes it too. Images per request has no maximum of 10, which no provider set. An agent, model or tool with no name reads Unnamed agent, Unnamed model or Unnamed tool everywhere: before, the tree said Identity, Model binding or Tool, the map said New agent, and the editor said Unnamed. The Labels page now lists every line a profile can change except the provider and protocol lines: Blocked messages and Thoughts under Visitor reads, and Detectors, Sign-in, User data, Turn context, Structured replies and Compaction under Model reads. Before, these 36 lines were not on the page, even in a search.

- **A side panel in a narrow layout keeps its minimum.** Before, `SidePanel` and `ConsoleFrame` set a percentage maximum. In a narrow layout that maximum was below the 280px minimum, and Astryx warned that the minimum was above the maximum. Now the maximum never goes below 280px.

- **OpenRouter decisions see their images.** Before, `openRouterDecisions` sent images in an `assets` map, which OpenRouter ignores, so the model answered without them. Now each image goes where its reference is in `state`, instructions, or criteria, as an `image_url` part. A reference inside a longer string, such as "Which item matches <ghs02>?", works too, as it does on TypeSafe.
- **A decision sends only the images it references.** Before, every image in `assets` went to the provider, and the disclosure check and the trace saw them all. Now the kernel sends only the images that a string in `state`, instructions, or criteria references, and the disclosure check and the trace see only those.
- **A box answer is drawn on the right image or none.** Before, `TheoremDecision` guessed a box's image from the first field its instructions named, else the first image the state named, else the first image held. Now it uses the question's `image`, else the decision's only image. When it cannot tell, it draws the box in a frame that stands for the whole image.

- **A structured turn with tools can call its tools.** Before, a turn with `outputs.structured` and function tools sent the schema as a response format beside the tools. Many OpenRouter endpoints refused the request, and many models answered in JSON at once without calling a tool. Now the kernel offers the turn one more tool, `ANSWER_TOOL`, with the schema as its input, and sends no response format. The model's text streams to the host as `text`, as progress. The answer tool's input streams as `structured_draft` and gives the `structured` event. A turn with no function tools still sends the schema as its response format.
  - The answer ends the turn with stop `completed`: tool calls in the same step do not run.
  - When the model stops without calling the answer tool, the turn repairs the reply while `outputs.validation.maxRetries` has a retry left. Otherwise the turn ends with a `bad_response` error.
  - Change what the model reads with the labels `structured.answer_tool` (the tool's description) and `structured.answer_missing` (the repair).
- **A refused Chat Completions call says why.** Before, when `openAi` or `openRouterOpenAi` got an HTTP error, `errorInternal` held only the status, such as "Chat Completions HTTP 400". OpenRouter puts the upstream reason in `error.metadata`, so a 400 read only as `unsupported`. Now `errorInternal` holds the body's `error.message` and every field outside the standard ones, for example `{"metadata":{"raw":"…","provider_name":"Nvidia"}}`. An error row in a stream reads the same way. The kind does not change.
- **The compactor reads a tool result's images.** Before, the compactor got a tool result's files inside the assistant message that holds the result. Chat Completions takes only text there, and some endpoints, such as Nvidia's on OpenRouter, refused the call with HTTP 400, so the compaction failed. Now the files follow the result in a user message, led by the new label `compaction.tool_files`.
- **A structured reply that does not parse gets its retry.** Before, validation checked only a reply that parsed as JSON. A reply cut at `length`, such as a model that pads its JSON with blank lines until the output limit, ended the turn at `length` with no `structured` event and no retry, even with `outputs.validation.maxRetries` set. A reply that was not valid JSON ended with a `bad_response` error and no retry. On a free OpenRouter model, 4 of 18 structured turns were cut this way, and `continueFrom` did not recover any of the 4. Now validation repairs both while a retry is left. The repair carries the reply's text and the new label `structured.cut_off` or `structured.not_json`.
- **Chat Completions sends the images an assistant message holds.** Before, `openAi` and `openRouterOpenAi` put an assistant message's `parts`, such as a photo the host sent the user, in its content as `image_url`. Chat Completions takes only text there, and some endpoints, such as Nvidia's on OpenRouter, refused the call with HTTP 400. Now the files leave a marker in the assistant message and follow it in a user message, after the results of any calls it made.
- **A host stage's question is asked once.** Before, a `pre_tool` `onStage` handler that answered `confirm` asked again on every granted resume, so the call never ran. Now the granted resume runs the stage again, and its `confirm` asks nothing more. A `pre_tool` handler also reads `approved`: the user approved the call where it stopped, at its permission or a confirmation.
- **A replayed tool shows its output, not what the model read.** Before, Replay exchange showed a remote tool's result as the model read it: fenced in `<tool_data>`, as one line of text. Now it shows the tool's raw output, `theorem.tool.data`, as the live chat does.
- **A live call reads its opening context before the first input.** Before, `SessionRequest.context` went to Gemini Live as its own message after the socket opened. Gemini does not keep that message in order with realtime input, so a host that sent text at once, such as an opening prompt, could have the model answer before it read the context. On a free key, the model then called tools to find what the context held. Now the kernel reads the context before setup, and `geminiLive` sends it as one user turn at the end of the opening history, which the model reads before any input. A protocol's `openSession` request carries the texts as `context`. A later `sendContext` is sent as before.
- **The studio asks once before a tool that writes.** Before, the studio changed each such tool's registered permission to `always_confirm`. A project's own check that read the registration, such as a preflight, then asked a second time. A `session_consent` tool also asked twice on its first run. Now the studio asks through a stage of its own (`onStage` on `createTheoremHandler` and `createTheoremHostHandler`), and the registration stays as the project set it.
- **A profile's labels can no longer name a line it cannot change.** Provider and protocol errors, and the decision box hint, are read only from `overrideLabels`; `HOST_LABEL_KEYS` lists them, and a profile whose `labels` sets one is refused. `provider.duplicate_call` in a live session no longer read the profile's labels when the same line in a turn did not.
- **The studio's Labels page shows every line a profile can change.** A test now fails when a line has no area.
- **Studio: options left unset say "Provider default".** They said "Protocol default", but every unset option keeps the provider's default.
- **Studio: Switching is off limits below two models.** The picker shows only with two models or more; the editor now says so.
- **Studio: text cut at its length limit says so.** An id or handle pasted past its limit was cut without a word.
- **Studio: the Labels page says "Add" for a section the profile leaves out.** "Open" also added the section, without saying so.

## Breaking Changes

- **A profile's `labels` cannot set a host line.** `defineProfile` refuses `labels` with a `HOST_LABEL_KEYS` key; set it with `overrideLabels`.

- **Context is fenced in `<turn_context>`, not `<page_context>`.** Context reaches the model on any channel, not only from a page, such as from a host's server over iMessage. The fence tag `wrapContext` writes is now `<turn_context from="client">` or `<turn_context from="server">`. The default `context.note` now says the text is what the app or the host reports about the user and this conversation. A prompt or a `context.note` override that names `<page_context>` must name `<turn_context>`.
- **A live protocol sends the opening context.** The kernel no longer calls `sendContext` with `SessionRequest.context` after `openSession`. The `openSession` request carries it as `context` instead (see What's Fixed). A live protocol you wrote must send `request.context` after `history` and before any input, or the model does not get the opening context.
- **Turn history holds the model's own text.** The `history` a stage handler gets in `StageContext`, and the `history` a protocol gets in its request, now hold more assistant messages (see What's Fixed):
  - A step that wrote text and then called tools adds two assistant messages: one with the text, then one with the `tool_calls`. The kernel does not merge them.
  - A `before_end` inject lands after an assistant message with the answer.

  This affects a stage handler that finds a message by its position in `history`, and a protocol you wrote that expects user and assistant messages to alternate. Find messages by `role` and `tool_calls`, not by position. If your protocol's upstream API does not accept two assistant messages in a row, merge them in the protocol.
- **Failure kinds and codes follow what happened.** These changes come from the fix above (see What's Fixed):
  - `ErrorKind` has a new member, `conflict` (HTTP 409). A `switch` over every kind needs a `conflict` case, and a label override set can add `error.conflict`. A provider's HTTP 409 now reads as `conflict`, not `unsupported`.
  - `ErrorKind` has a new member, `not_found` (HTTP 404), with the label `error.not_found`. A conversation ref the store cannot open has kind `not_found`, so the web handler answers 404, not 400. Its `errorCopy.key` is still `session.conversation_unknown`. A route or method the web handler does not serve answers 404 with kind `not_found`, not 405 with `request`. A provider's HTTP 404 still reads as `unsupported`.
  - `DecisionError` has more codes, one for each kind: `invalid_config`, `conflict`, `invalid_input`, `not_allowed`, `busy`, `unsupported`, `refused`, `blocked`, `declined`, `failed` and `internal`. A decision HTTP 400 now has code `unsupported`, not `invalid_request`, as a 400 on a turn reads. The kind of each 4xx status may change again in a later release. A 503 or 529 has code `busy`, not `unavailable`.
  - A remote tool failure can have code `request_failed`, `cancelled` or `timeout` where it had `network_error`.
  - A fetch that fails in Theorem's guarded fetch, such as `discoverAuthServerMetadata`, now throws a `TheoremError` with kind `network`. The error it threw before, such as a `TypeError`, is its `cause`.

  This affects a host that switches on `DecisionError.code`, or on a tool failure's `code`, and code that catches a `TypeError` from the guarded fetch. Switch on `kind` instead, or add the new codes.
- **A coordinator's `begin` runs at the hand-off.** A `ToolExecutionCoordinator` gets `begin` after the `running` tool event, not before it, and only when the call reaches its destination (see What's Fixed). A call that fails before that gets `settleNotStarted`, where it got `begin` and `settle`. A call that stops before that gets no call, where it got `begin` and `markUncertain`. An error after the claim has its cause's kind, not `unavailable`. A call to run a running or uncertain operation has the new kind `conflict`, so the React handler answers HTTP 409, not 503, as [Stripe](https://docs.stripe.com/error-low-level) and the [IETF Idempotency-Key draft](https://datatracker.ietf.org/doc/html/draft-ietf-httpapi-idempotency-key-header) answer a retry of a request that is still running. A refused page answer is `request`, `conflict`, `timeout` or `cancelled`. This affects a host that counts `begin` calls, code that switches on `unavailable` to find an unresolved execution, and a client that retries on 503. Read `errorCopy.key` `tool.execution_uncertain` instead.
- **`text` events can start with a blank line.** The first `text` event of a later model call in the same reply can now start with `\n\n` (see What's Fixed). This affects a host that puts its own separator between the text of two model calls, and tests that compare the exact reply text. Remove your own separator, and update the expected text.
- **`StageApplyWarningCode` has a new member.** `StageApplyWarningCode` from `@theoremjs/agents` now includes `'inject_released_invalid'`. A `switch` that must cover every code fails to type-check until you add this case.
- **`stage.injected` carries each inject's messages.** Each entry of a `stage` event's `injected` is now `{ id, messages }`, not `{ id }`. `messages` holds the history messages the inject added, after the `injected` guardrails. This affects code that builds these events (test fixtures, a host that replays events) and tests that compare them exactly. Add the inject's messages.
- **What the profile must not give away is flagged, not stopped.** `canary_leak`, `prompt_leak`, `marker_leak` and `ungiven_images` now default to `flag` at every boundary they read. Before, they defaulted to `block` in a reply, a structured reply and a Live reply, and to `redact` in a thought; `canary_leak` also defaulted to `block` in a tool call. Theorem still reads all of these for leaks and reports each one in a `guardrail` event with action `flag`. The reply, the thought and the tool call go out as written. The turn no longer ends with a `safety` error, and `guardrails.blockedReply` does not run for these leaks. The turn ends as it would without the leak: `done.stop` is the model's own stop, not `{ kind: 'filtered', native: 'egress' }`, and a reply's leak is reported at stage `output_delta`, not `output_final`. This affects a host that counts on Theorem to keep a leak from the user. To stop a leak, set the detector to `block`, for example `detect: { canary_leak: 'block' }`. To replace it with a placeholder such as `OMIT_CANARY`, set it to `redact`.
- **Personal data, secrets and injection are flagged, not taken out.** `ids`, `financial`, `network`, `credentials` and `injection` now default to `flag` in what comes in: the user's text, history, slots, attachments, steering, the system parts Theorem scans, and tool output and failures. Before, they defaulted to `redact` there, so the model read a placeholder. `credentials` also defaulted to `redact` in what a tool shows the person (`tool_shown_*`) and in a reply and a structured reply; it now defaults to `flag` there too. Theorem still finds each match and reports it in a `guardrail` event with action `flag`, and the text goes on as written. This affects a host that counts on Theorem to keep personal data, secrets or injected instructions from the model or the user. To take them out, set the detector to `redact`, for example `detect: { injection: 'redact', credentials: 'redact' }`. To stop the turn instead, set it to `block`.
- **The studio has no Reset everything.** The editor's Reset menu is gone. Reset each agent, tool, and provider from its row in the tree. On a project, Discard all edits stays in Settings and the save menu.
- **`TheoremTransport` and `SteerInbox` take a stop.** A `TheoremTransport` you wrote must add `stop({ turnId })`, which stops the turn or rejects when the host is not running it. A `SteerInbox` you wrote must add `stop(turnId)`, which returns `false` when no turn is open, and `stopped(turnId)`, which settles `true` once the turn is stopped and `false` once it closes.

- **`failedDecisionTraces` is gone.** Use `failedTraces` from `@theoremjs/web/client`, which does the same.
- **`DecisionQuestionView.field` is now `image`.** A box question's view gives its image as the question sets it: a reference, or the state field that holds one. It no longer falls back to the first field the instructions name. Read `image`, not `field`.
- **`openRouterDecisions` takes no options.** It no longer extends `systemOne`. OpenRouter needs no `images` opt-in and puts a request with an image in long context itself, so a binding with `options: { images: true }` or `longContext` is refused. Remove the options, and use OpenRouter's model ids, such as `typesafe/jev-1.14`.

- **Theorem sets no provider limits of its own.** Before, a call that no host limited stopped after 120 seconds, a live session after 30 seconds to open, and a step at 64 MiB, 100,000 events or 32 tool calls. Now each limit that nobody sets is no limit, and the provider's own limits apply. If you relied on these cut-offs, set them in `models.*.limits` or in the host's `limits`. Every field of `ProviderLimits` is now optional.
- **`resolveProviderLimits` is gone.** No defaults are left to merge. Check limits with `providerLimitsSchema.parse`.
- **Tools read and fetch with no limits of their own.** Before, an HTTP or MCP tool failed `response_too_large` past a 4 MiB body, and a tool's `images` hook fetched at most 4 pictures, 5 MiB each, 10 MiB in all, 15 seconds each. Now each limit is unset unless the tool sets it. If you relied on these cut-offs, set `maxResponseBytes` and `imageLimits` (`count`, `bytes`, `totalBytes`, `timeoutMs`) on the tool. In the studio, Max response on an HTTP or MCP tool sets `maxResponseBytes`. `MAX_TOOL_RESPONSE_BYTES` and `MAX_TOOL_IMAGES` are gone.
- **A repair reads this turn only.** Before, a validation or egress retry sent the model the whole conversation again. Now, from the first retry on, the model reads only this turn: its input, its tool calls and results, the replies sent back, and the repairs. When the host passed earlier history, the turn's `done` carries no `providerState`, so the next turn sends its history in full. This affects a profile whose repair needs a fact from an earlier turn. Put that fact in the turn's input.
- **MCP sessions have no limit of their own.** Before, the kernel kept at most 256 MCP sessions and dropped one after 30 idle minutes. Now it keeps each session until the server ends it, unless the tool sets `session`: `idleMs` for how long one may sit unused, and `max` for how many the tool keeps. If you relied on these cut-offs, set `session` on the tool. In the studio, an MCP tool's Session section sets them.
- **A session holds any size unless its store declares a capacity; `sessionLimits` is gone.** Before, the web handler's `sessionLimits` refused a write past 32 gates, 128 operations, 256 checkpoints, 2,048 permissions, 32 MiB of state, or 256 KiB for one invocation or result, and a result too large left the call unresolved. Now a `TheoremSessionStore` with a real limit declares `capacity`: `maxStateBytes` for one session and `maxOutcomeBytes` for one result. `createMemorySessionStore` declares none unless you pass `capacity`, so it keeps a result of any size. A full session drops its oldest settled results, then its oldest provider checkpoints. It refuses a new call before it runs only when open work alone does not fit, and the user reads the new label `session.full`. A result past `maxOutcomeBytes` settles as the call's `result_too_large` failure. A `ToolExecutionCoordinator` you wrote may declare `maxOutcomeBytes`. If you relied on `sessionLimits`, pass `capacity` to `createMemorySessionStore`, and add `capacity` to a store you wrote that has a real limit. `resolveSessionLimits` and `TheoremSessionLimits` are gone; `TheoremSessionCapacity` replaces them.
- **A gate, a request and a page tool call have no limit unless the host sets one.** Before, a gate expired after 30 minutes, the handler refused a request body over 16 MiB (and a live relay a frame over 16 MiB, whatever `maxRequestBytes` said), and a tool call the page ran settled as timed out after 20 seconds, which no host could change. Now `gateTtlMs` (handler, session boundary and `runSession`) and `maxRequestBytes` are unset unless you set them, and the new `pageToolTimeoutMs` (handler and session boundary) sets the page's deadline. `parseLiveOpenMessage` and `parseLiveClientMessage` take an optional `maxBytes`. In the studio, a Live call the browser has not answered waits for it, unless `clientCallTimeoutMs` is set. If you relied on these cut-offs, set them. The web README lists the defaults that remain.
- **Host patterns have no count or length limit.** Before, a detector took at most 64 host patterns, each at most 1,024 characters. Now it takes as many as you give it, each as long as you write it. Each pattern adds to what every view costs to read. A pattern that can run away (catastrophic backtracking) is still refused. `MAX_PATTERNS` and `MAX_PATTERN_LENGTH` are gone from `@theoremjs/agents/guardrails`.

- **A structured turn with tools answers through a tool.** The request a protocol gets for such a turn has `structured: null` and one more entry in `wireTools`, named `ANSWER_TOOL` (see What's Fixed). Its `text` events are progress, not the answer: read the answer from `structured`. A profile with `outputs.structured` that offers its own tool named as `ANSWER_TOOL` gets a `config` error. Rename that tool.
